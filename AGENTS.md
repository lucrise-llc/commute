# AGENTS.md

This file is for coding agents. README.md explains Commute to people. PRD.md holds the requirements, D1 to D11.

## Project overview

Commute lets many agents work on one repository at the same time. It is our entry in Cloudflare's "Build the next
GitHub" competition. `poc/` holds the spike that settled the platform risks. Its code is not product code, and the
tooling below ignores it. `poc/FINDINGS.md` has the measured behavior of Artifacts, containers, and push events.

## Stack

| Part | Choice |
|---|---|
| Language | TypeScript 6, strict |
| Runtime and packages | Node 24.21 (`.node-version`), npm workspaces |
| Worker | Cloudflare Workers, Hono, zod, run and deployed with Wrangler |
| API contract | `@hono/zod-openapi` routes, an OpenAPI 3.1 document, and a client generated by `@hey-api/openapi-ts` |
| Coordinator | One Durable Object per project, with SQLite storage |
| Runners | Durable Objects with a container (`this.ctx.container`), built from our Dockerfile with git |
| Repositories | Cloudflare Artifacts, through the Workers binding and git smart HTTP |
| Console | React 19, Vite, Tailwind CSS 4. The Worker serves its build as static assets |
| CLI | TypeScript that Node 24 runs directly, with `parseArgs` from `node:util` |
| Lint, format, unused code | oxlint with type-aware rules, oxfmt, knip |
| Task runner | Turborepo, for `dev` and `deploy` |
| OpenAPI check | Vitest, which compares the served document with `openapi.json` |

The console adds Radix UI primitives, TanStack Query, and React Router when the first view needs them.

## Layout

```
apps/server/            The `commute` Worker
  worker/               Worker code: the Hono app, the Commute remote, the coordinator, the runners
  runner/               Dockerfile of the runner image
  test/                 The OpenAPI document check
  openapi.json          The API contract, written from the routes
apps/console/           The React console, a Vite project
apps/cli/               The `commute` CLI
packages/api-client/    The typed API client, generated from openapi.json
```

## Dev environment

- Run `npm install` at the root. Use the Node version in `.node-version`.
- `npm run dev` builds the console, then starts two servers:
  - `http://localhost:8787` is `wrangler dev`. It serves the API, the Commute remote, and the last console build, as
    production does. Agents and verification runs use this address.
  - `http://localhost:5173` is the Vite dev server of the console. It reloads on save and proxies `/api`, WebSockets
    included, to port 8787. Use it for console work.
- Artifacts has no local simulator. The Artifacts binding sets `remote: true`, so `npm run dev` calls the live service
  on the Lucrise account. Run `npx wrangler login` once. Dev uses only the `commute-dev` Artifacts namespace.
- Runner containers run in local Docker. Docker must run for `npm run dev` and for a deploy, which builds the image.
- `wrangler.jsonc` pins the Lucrise account with `account_id`, because the Wrangler login can reach more than one
  account.
- Local secrets go in `apps/server/.dev.vars`, next to `wrangler.jsonc`. Git ignores the file.
- The Lucrise account also runs production Workers. Create only resources whose names start with `commute`. Delete
  nothing that this repository did not create.

### Common commands

```bash
npm install                          # also installs the pre-commit hook
npm run dev                          # the Worker on 8787 and the console dev server on 5173
npm run check                        # typecheck, lint, format, knip: the gate before a push
npm run typecheck
npm run lint                         # lint:fix applies the autofixes
npm run format                       # format:write rewrites
npm run knip                         # unused files, exports, and dependencies
npm run api:generate                 # rewrite openapi.json and the API client after a route change
npm run test -w @commute/server      # the OpenAPI document check
npm run build -w @commute/console    # production build of the console, which the Worker serves
npm run cf-typegen -w @commute/server  # regenerate worker-configuration.d.ts after a wrangler.jsonc change
npx commute                          # run the CLI from the workspace
```

To try the agent flow locally, create a project, push a first commit to its trunk remote with the returned token,
then start changes:

```bash
curl -X POST localhost:8787/api/projects -H 'content-type: application/json' -d '{"projectId":"demo"}'
COMMUTE_URL=http://localhost:8787 COMMUTE_PROJECT=demo npx commute start "<intent>" --paths <path,path>
cd c-1 && git push && npx commute wait
```

## Verification

- The demo has no test suite. Do not write tests.
- `npm run check` is the gate before a push: types, lint, format, unused code, and the check that `openapi.json` and
  the generated client match the routes.
- Verify a change by running its flow against `npm run dev` with the CLI and plain git, as an agent does. Put the
  commands and their output in the PR.
- A UI change attaches screenshots to its PR.

## Architecture and conventions

- Commute is a hosted platform: one deployment serves the projects of many teams. Scope state, names, and compute by
  project, and share nothing across projects that holds a team's data or runs its code. The demo has no auth and no
  tenant model; when they arrive, the tenant scopes the project ID, and the naming helpers in `worker/repos.ts` and
  `worker/runner-pool.ts` are the places that change.

- `apps/server/worker/index.ts` is the Worker entry. `worker/app.ts` builds the `OpenAPIHono` app. JSON routes are
  under `/api/*`. The Commute remote is under `/git/*`. Every other path serves the console build from
  `apps/console/dist`.
- The console calls the API only through `@commute/api-client`, on the same origin. It imports nothing from
  `apps/server`.
- The coordinator owns the life of a change. Routes and the Commute remote call it through `c.env.COORDINATOR`, one
  Durable Object per project.
- Merge checks run in `Runner` Durable Objects, two per project, each with a container from
  `apps/server/runner/Dockerfile`. The image sets the command, and `start()` passes only `enableInternet`. The
  coordinator queues checks and runs them from its alarm, never inside a request.
- A change token never appears in a URL, an argument, or output. `commute start` writes it to `.git/commute/token`
  with mode 600, and a repo-local credential helper (`commute credential`) gives it to git for the Commute server
  only.
- Each JSON route lives in `worker/routes/<name>.ts`. The file exports `<name>Route` from `createRoute` and
  `<name>Handler`, and `worker/app.ts` registers the pair. Each route sets an `operationId` that starts with a verb
  (`getHealth`, `listChanges`, `startChange`). The generated client names its functions after it.
- After a route or schema change, run `npm run api:generate` and commit `apps/server/openapi.json` and
  `packages/api-client/src/generated` with the change. `npm run check` and CI fail when either one is stale. Never
  edit generated files.
- Register each WebSocket event schema as a named OpenAPI component, so that the generated client also carries its
  zod schema.
- The OpenAPI check loads `worker/app.ts` in Node. That file and its imports must not import `cloudflare:workers` at
  runtime. They reach Durable Objects through `c.env` and import the classes with `import type`.
- The CLI and the API client run on Node without a build, so their relative imports end in `.ts`. Code that Vite or
  Wrangler bundles imports without an extension.
- Parse every input that crosses a boundary with zod, and derive its type with `z.infer`. Boundaries are request
  bodies, git protocol data, WebSocket messages, Artifacts responses, and environment bindings.
- Throw errors; do not return result objects. An error message is a stable code in `SCREAMING_SNAKE` case, such as
  `CHANGE_NOT_FOUND`.
- Log one structured record per request or job, so that Workers Logs can query its fields. Logs go through
  `worker/log.ts`, the one Worker module that oxlint allows to call `console`.
- Give every input and every loop a named bound: push size, tree reads, runner jobs, and retries.
- Commit `worker-configuration.d.ts` with the `wrangler.jsonc` change that produced it.
- A Worker with static assets does not receive `ctx.access`. The Worker verifies the Access token in the
  `Cf-Access-Jwt-Assertion` header itself. Protect the console with a hostname Access application, because a
  Worker-level Access policy rejects WebSocket upgrades with `403`.

### Naming

- Files use kebab-case, including React components.
- Use named exports. A default export is only for a file that a framework loads: the Worker entry and config files.
- Identifiers use the `Id` suffix (`changeId`). Booleans start with `is`, `has`, `should`, or `can`.
- Constants are `UPPER_SNAKE_CASE` at the top of the file. Zod schemas are `camelCaseSchema`, and their inferred types
  are `PascalCase`. Component props types are `<ComponentName>Props`.
- Do not use `enum`. Use an `as const` array with `z.enum()`.

## General rules

The tag after a rule names the tool that enforces it.

1. No single-character names, except `c` for the Hono context. (oxlint)
2. No `as` type assertions. `as const` is allowed. Parse with zod instead. (oxlint)
3. A function with more than one parameter takes one object parameter, with its type defined above the function. A
   signature that a framework sets is the exception: mark it with
   `// oxlint-disable-next-line max-params -- framework signature`. (oxlint fails at three or more)
4. Use `type`, not `interface`. (oxlint) Write object types on several lines. (review)
5. No magic numbers. Name them as constants. Numbers from 1000 up use separators: `1_000`. (oxlint)
6. No `enum`, `namespace`, or parameter properties. (tsc, `erasableSyntaxOnly`)
7. No nested ternaries. Prefer `if`/`else` and `for ... of` when they read more clearly. (oxlint)
8. Await every promise. Do not use the `void` operator. (oxlint)
9. Mutations are idempotent. A push handler, a coordinator write, and a runner job each survive a retry.
10. Write a comment only for intent or a constraint that the code cannot show.
11. Do what was asked, and nothing more. Fix the debt in code you touch. Do not bundle unrelated fixes.
12. Create a file or a document only when the task needs it.
13. One PR holds changes that share a root cause or depend on each other. Split changes that need separate rollback.

## CI, PRs, and commits

- CI runs `npm run check` on each pull request and on `main`.
- The pre-commit hook runs lint-staged. It runs oxlint with fixes and oxfmt on staged files, and the typecheck when a
  TypeScript file is staged.
- `oxlint --fix` applies one pass. When a staged file has two or more misordered imports, the fixes overlap, the hook
  blocks the commit, and lint-staged reverts the fix. Run `npm run lint:fix`, stage the result, and commit again.
- Commits use Conventional Commits with a scope, such as `feat(coordinator): ...`.
- A PR body starts with the motivation, then one sentence on what changes, then optional bullets. It has no Problem,
  Solution, Changes, or Testing sections. A UI change includes screenshots or an ASCII sketch of the layout.
- A deploy publishes. Only a person runs `npm run deploy`, which builds the console and deploys the Worker.
